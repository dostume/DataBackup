## 重要：本环境 GCM 段错误，取 token 的正确方式
本次会话 GCM（git-credential-manager get）在 bash 下段错误（exit 139）或返回空，`git push` 报 "could not read Username"。解决：用**系统 Git**（`C:\Program Files\Git\cmd\git.exe`）配合 **wincred** helper 成功读出 token：
```
printf "protocol=https\nhost=github.com\n\n" | "/c/Program Files/Git/cmd/git.exe" -c credential.helper=wincred credential fill
```
输出 `username=dostume` + `password=gho_...`（GitHub OAuth token，存于 Windows 凭据管理器 `git:https://github.com`）。
推送可用：`git -c credential.helper= -c http.extraheader="Authorization: Basic $(printf 'dostume:%s' "$GITHUB_TOKEN" | base64)" push origin main`

## WebDAV 上传 PUT 405（commit 6adb3504）——AList 服务器端问题诊断
用户提供 log_1787884507085.txt：备份到 AList WebDAV（`http://0.0.0.0:5244/dav/cmcc/测试`，cmcc=中国移动云盘挂载）时，**所有 MKCOL/PUT 都被服务器拒绝**：
- MKCOL `cmcc`、`cmcc/测试` → 405（挂载根/一级目录创建被拒）
- MKCOL 更深目录 → 409（父目录实际不存在）
- PUT 全部文件（apk/user/user_de/data/obb/DataBackup.apk）→ **405 Method Not Allowed**

根因：**AList 服务器端问题**，非 app 代码 bug。AList 挂载中国移动云盘（cmcc）时 WebDAV 写操作（MKCOL/PUT）不可用，GitHub AlistGo/alist issue #7819「中国移动云盘上传405 Method Not Allowed」正是此问题。任何 WebDAV 客户端（含 Rclone）都无法绕过。

客户端改进（已推送 6adb3504，CI Run 待下载）：
- `mkdirRecursively()`：MKCOL 405/409 时用 `exists()` 二次确认，目录真不存在则抛明确 IOException（不再静默掩盖），避免目录缺失被误判"已存在"、直到 PUT 全部失败才发现。
- `upload()`：PUT 405 时输出明确诊断日志（提示服务器不支持写入，如 AList+中国移动云盘）。
- `exists()`：非 405/409 失败时也打日志，便于诊断。

服务器端解决建议（给用户）：
1. 升级 AList 到修复版本（#8564 推荐 pongfcnkl/alist11 分支版本）。
2. 在 AList 中确认该存储是否可写 / 更换存储挂载（cmcc 移动云盘 WebDAV 写支持差）。
3. 验证命令：`curl -u 用户:密码 -X MKCOL http://AList:5244/dav/test_dir -i` 和 `curl -u 用户:密码 -T test.txt http://AList:5244/dav/test.txt -i`，看是否 405。
4. 检查 AList WebDAV 用户权限（guest 用户可能只读）。

## 更正：用户实际用 OpenList（非 AList），405 根因是账户权限不是服务器 bug
用户反馈："我用的是 openlist，启用 guest 账户给所有权限后可以用了"。并问 app 上传是否没走设置的 admin 账户。

结论（已验证代码）：
- **app 一定使用设置里配置的账户**。`WebDAVClientImpl.kt:89-93` 在 `entity.user` 非空时对每个请求（含 PUT）做抢占式 Basic 认证；`WebDAVSetup.kt:69-70` 用户名/密码直接存 `entity.user/pass`。不存在"绕过 admin 走 guest"的逻辑。
- 之前"AList+cmcc 服务器不支持写"的判断在 OpenList 场景下需修正为**账户权限不足**。OpenList 的 WebDAV 权限模型（doc.oplist.org + DeepWiki 4.2）：
  - 读需要「WebDAV 读取」权限位；
  - **写（PUT/MKCOL）需要「WebDAV 管理」AND「写入」两个权限位同时开启**，仅开 WebDAV 管理不够；
  - Move/Copy/Delete 还需对应文件系统权限（重命名/复制/删除）。
- 用户给 guest 勾了全部权限所以成功；admin 缺「WebDAV 管理」或「写入」位导致 405。
- 处理方向：OpenList 后台 → 用户 → admin → 权限 → 勾选「WebDAV 管理」+「写入」（及其他需要的），无需改 app 代码。
- 其它 OpenList 405 诱因（排查备用）：版本 bug（issue 建议 4.0.8/4.1.1）、site_url 设置、rclone 大文件 5 分钟超时、115 驱动大文件 405（issue #1252）。
